# Консультации НФ НИТУ МИСИС

Полный исходный проект Flask + PostgreSQL: студент записывается на очное занятие,
преподаватель составляет расписание, администратор управляет данными через кабинет.
Шаблоны Jinja, CSS и JavaScript поставляются локально; CDN не нужны.

## Быстрый запуск через Docker Desktop

Нужны работающий Docker Desktop с Linux containers и Python для создания `.env`.
Первое скачивание образов и зависимостей требует интернета. После подготовки сайт
и база работают в локальной сети без интернета.

1. Распакуйте архив в папку с коротким путём, например `C:\Projects\consultations`.
2. Откройте терминал в распакованной папке `consultation_portal`.
3. Выполните:

```powershell
py scripts/configure.py
docker compose up -d db
docker compose build web
docker compose run --rm web alembic upgrade head
docker compose run --rm web flask --app wsgi seed-demo
docker compose up -d web
```

4. Откройте [сайт на своём компьютере](http://localhost:8000).

На Windows ту же последовательность выполняет `start_windows.bat --seed`.
Для дальнейших запусков — `start_windows.bat` или `docker compose up -d`.
Повторный `seed-demo` не меняет данные или пароли: при непустой БД команда откажется
добавлять демонстрационный набор. После сброса пароля не нужно заново заполнять БД.

Если Python пока не установлен, скопируйте `.env.example` в `.env` вручную,
укажите собственные значения SECRET_KEY, POSTGRES_PASSWORD и пароля pgAdmin;
тот же POSTGRES_PASSWORD укажите в DATABASE_URL. Затем выполняйте Docker-команды.

## Подключение pgAdmin

База данных хранится в PostgreSQL. pgAdmin — программа для администрирования этой базы.
Для веб-версии pgAdmin из комплекта:

```powershell
docker compose --profile tools up -d pgadmin
```

Откройте [pgAdmin](http://localhost:5050). Вход — `PGADMIN_DEFAULT_EMAIL` и
`PGADMIN_DEFAULT_PASSWORD` из вашего `.env` (это отдельные данные, не аккаунт сайта).
Зарегистрируйте сервер: Name `Consultations`, Host `db`, Port `5432`, Maintenance
database `consultations`, Username `consult_app`, Password — `POSTGRES_PASSWORD`.

Если используете уже установленный на компьютере pgAdmin, укажите Host `localhost`.
Таблицы находятся в Databases → consultations → Schemas → public → Tables.
Установка pgAdmin без работающего сервера PostgreSQL не создаёт базу данных.

Для компьютера с Python 3.9 также приложена инструкция `docs/PYTHON39_WINDOWS.md`.

## Запуск с установленным PostgreSQL без Docker

Рекомендуемая среда: Python 3.11, PostgreSQL 16, pgAdmin 4. Исходники не требуют
синтаксиса новее Python 3.9; конкретный старый Python и его библиотеки необходимо
проверить на вашем компьютере. Самый воспроизводимый вариант использует Python 3.11.

1. В pgAdmin создайте роль `consult_app` с правом входа и собственным паролем.
2. Создайте базу `consultations`, назначив владельцем `consult_app`.
3. В Query Tool базы `consultations`, от владельца базы или postgres, выполните:

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;
```

4. В терминале из папки проекта:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python scripts/configure.py
```

5. Отредактируйте DATABASE_URL в `.env`: укажите пароль роли, имя БД, сервер и порт.
Специальные символы в части пароля URL кодируются по правилам URL; проще применить
длинный пароль из латинских букв и цифр. Сгенерированное SECRET_KEY сохраните.

```powershell
.venv\Scripts\alembic upgrade head
.venv\Scripts\python -m flask --app wsgi seed-demo
.venv\Scripts\waitress-serve --listen=127.0.0.1:8000 wsgi:app
```

На Linux команды те же, путь к исполняемым файлам окружения — `.venv/bin/`.
Для разработки с автоматическим перезапуском допустим `flask --app wsgi run --debug`;
для доступа студентов используется Waitress.

## Первая проверка за 15 минут

1. Войдите студентом, просмотрите профиль и запишитесь на «Базы данных».
2. Выйдите. Войдите преподавателем и откройте соответствующее занятие — запись
   студента видна в списке. Проверьте фильтр группы и Excel-выгрузку.
3. Попробуйте создать пересекающееся занятие: сервер должен отказать.
4. Войдите администратором: добавьте группу, дисциплину, второго преподавателя,
   закрепите дисциплину. Добавьте студента только по номеру, группе и курсу.
5. Войдите новым студентом, укажите ФИО, затем убедитесь, что повторное изменение
   требует обращения к администратору.
6. Проверьте светлую и тёмную темы, смену пароля, отмену записи и восстановление входа.

Для испытания пересечений студента создайте второго преподавателя через админский
кабинет: одному преподавателю пересекающиеся занятия создать нельзя.

## Если администратор заблокирован

Пароли преподавателя и администратора различаются, но блокировка принадлежит общему
логину. Если заблокирован единственный администратор, откройте терминал сервера:

```powershell
docker compose exec web flask --app wsgi recover-admin --login lxrdx
```

При обычной установке: `.venv\Scripts\python -m flask --app wsgi recover-admin --login lxrdx`.
Введите новый пароль дважды; он не отображается в терминале. Команда восстанавливает
администраторскую роль, снимает общую блокировку и завершает сеансы обеих ролей.
Новый пароль становится новым начальным паролем именно администраторской роли.
Доступ к консоли сервера должен быть только у ответственного за систему.

## Локальная сеть и сервер

В Docker установите `APP_BIND=0.0.0.0` в `.env`, затем `docker compose up -d web`.
Студенты открывают `http://IP_сервера:8000` в одной локальной сети. Для обычной установки
запускайте Waitress с `--listen=0.0.0.0:8000`. В брандмауэре разрешите TCP 8000 только
из нужной локальной подсети. Интернет-публикация в эту поставку не входит: готовые
инструкции размещения на своём сервере находятся в `docs/DEPLOYMENT.md`.
