# Локальная сеть и размещение на сервере

Для эксплуатации используется PostgreSQL 16, Flask и Waitress. Встроенный сервер
Flask предназначен для разработки: [официальная документация](https://flask.palletsprojects.com/en/stable/deploying/).

## Компьютер в университете

1. Запустите комплект по START_HERE.md и проверьте все три роли на localhost.
2. Назначьте серверу постоянный IP в нужной подсети совместно с ответственным за сеть.
3. Разрешите входящий TCP 8000 только из этой подсети. Откройте прослушивание
   `0.0.0.0` через APP_BIND (Docker) либо параметр Waitress (обычная установка).
4. Проверьте доступ со второго компьютера, время UTC+5, запись, список преподавателя
   и сброс пароля. Запишите реальные результаты в протокол испытаний диплома.
5. PostgreSQL/5432 и pgAdmin/5050 в compose привязаны к 127.0.0.1: студенты обращаются
   к сайту, а не к базе или pgAdmin. Если БД расположена отдельно, укажите её адрес
   в DATABASE_URL и разрешите PostgreSQL принимать подключения только от веб-сервера.

## Перенос на Linux-сервер

1. Подготовьте сервер с Docker Engine и Compose. Разместите проект и создайте собственный `.env`.
2. Перенесите базу через `pg_dump`/`pg_restore`, как описано ниже. На пустом стенде
   сначала `alembic upgrade head`; не запускайте seed-demo поверх перенесённой БД.
3. Замените все опубликованные начальные пароли на собственные. Для новых пользователей
   включите `FORCE_INITIAL_PASSWORD_CHANGE=1`. Существующие аккаунты, которые продолжают
   использовать начальные пароли, администратор сбрасывает после включения параметра,
   чтобы потребовать смену при следующем входе.
4. Сохраните длинное случайное SECRET_KEY, включите `COOKIE_SECURE=1`, поставьте HTTPS
   перед приложением. В compose оставьте APP_BIND=127.0.0.1. Пример Nginx — deploy/nginx.conf.
5. Получите сертификат для выбранного домена по процедуре вашей организации и укажите
   реальные пути к нему. Nginx-пример не работает до замены домена и путей сертификата.
6. Миграции выполняйте отдельной административной ролью БД. Для работающего приложения
   заведите роль с минимальными правами по deploy/runtime_role.sql и замените её в
   DATABASE_URL. В Docker для этого измените DATABASE_URL секции web.environment:
   она имеет приоритет над одноимённой переменной из env_file.
7. Повторите проверки, включая два одновременных запроса на последнее место. Проверьте
   перезапуск, резервную копию и восстановление на отдельной базе. Зафиксируйте версию
   образов и зависимостей, которая прошла испытания на сервере.

Режим «общий логин — разные пароли» и известные начальные пароли сохранены по ТЗ.
Общая блокировка позволяет закрыть обе роли, зная логин и исчерпав попытки. Для
эксплуатации этот компромисс следует обсудить с руководителем проекта; изменение
правила потребует согласованной правки ТЗ. Консольная команда recover-admin уже
предусмотрена для восстановления единственного администратора.

## Резервные копии

Скрипт использует установленный `pg_dump` той же основной версии PostgreSQL или новее:

```powershell
py scripts/backup.py backups/consultations_2026-11-08.dump
```

Для Docker на PowerShell, чтобы избежать повреждения бинарного файла перенаправлением:

```powershell
docker compose exec db pg_dump -U consult_app -d consultations -Fc -f /tmp/consultations.dump
docker compose cp db:/tmp/consultations.dump ./consultations.dump
```

Для восстановления сначала создайте **новую отдельную** БД `consultations_restore`:

```powershell
docker compose exec db createdb -U consult_app consultations_restore
docker compose cp ./consultations.dump db:/tmp/restore.dump
docker compose exec db pg_restore -U consult_app -d consultations_restore --no-owner /tmp/restore.dump
```

После восстановления подключите отдельный тестовый экземпляр сайта к этой БД
и сравните количество пользователей, занятий и записей. Не используйте `--clean`
на рабочей БД без отдельного плана восстановления. Копии хранятся вне сервера,
по расписанию организации; SECRET_KEY и `.env` сохраняются отдельно с ограничением доступа.
`docker compose down` оставляет данные в томах; `docker compose down -v` удалит тома
и данные, поэтому эта команда не применяется для обычной остановки.
