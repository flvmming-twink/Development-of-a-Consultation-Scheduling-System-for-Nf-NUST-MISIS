# Развертывание на Render

Проект подготовлен для Render Blueprint через `render.yaml` в корне репозитория.
Blueprint создает Docker web service `misis-consultations` и PostgreSQL
`misis-consultations-db`.

После подключения репозитория в Render выберите New > Blueprint и этот репозиторий.
Render использует `render.yaml`. На бесплатном тарифе pre-deploy commands недоступны,
поэтому контейнер при старте сам выполнит `alembic upgrade head` и команду
`flask --app wsgi seed-demo-if-empty`, затем запустит `python server.py`.
Повторные запуски не активируют удалённых администраторов и не меняют пароли.

Публичный адрес будет вида:

```text
https://misis-consultations.onrender.com
```

Тестовые входы после первого успешного деплоя:

| Роль | Логин | Пароль |
|---|---|---|
| Студент | `2300431` | `Student` |
| Преподаватель | `kurenkov.ee` | `Kurenkov` |
| Администратор | `lxrdx` | значение `DEMO_ADMIN_PASSWORD` в Render |
| Администратор | `flvmming` | значение `DEMO_ADMIN_PASSWORD` в Render |

Пароль администратора задается переменной `DEMO_ADMIN_PASSWORD` в Render. В
Blueprint она помечена как `sync: false`, поэтому значение вводится в панели Render
и не публикуется в репозитории. Она используется при начальном заполнении пустой
базы. Для уже существующих аккаунтов сохраняются текущие хеши паролей.

## Уведомления и корзина

`server.py` запускает Waitress и фоновое обслуживание с интервалом 60 секунд:
обновление курсов, оповещение о выпускниках, открытии записи и начале занятий,
удаление аккаунтов, находящихся в корзине 10 полных суток. PostgreSQL advisory
lock и уникальные ключи уведомлений предотвращают двойную обработку при
одновременном запуске экземпляров. Все данные сохраняются в PostgreSQL.

Ручной запуск обслуживания или запуск внешним планировщиком:

```text
flask --app wsgi maintenance
```

На бесплатном Render сервис засыпает после 15 минут без входящих запросов.
Во время сна фоновые задачи не выполняются. При пробуждении очистка запускается
снова; восстановление аккаунта уже запрещено после истечения 10 суток независимо
от фактического запуска очистки. Напоминания о занятиях, полностью прошедших во
время сна, задним числом не рассылаются. Для точной работы расписания круглосуточно
нужен постоянно работающий сервис или отдельный планировщик на сервере.
Источник: https://render.com/docs/free#spinning-down-on-idle.

Миграция `0002` сохраняет существующие аккаунты. Год поступления определяется
по окончанию названия группы. Кафедры существующих преподавателей администратор
назначает вручную: реальные названия не подставляются автоматически.
