## ТЗ на программу и роли пользователей

Назначение программы — запись на конкретные дополнительные очные занятия. «Курс» в профиле означает год обучения; учебное занятие принадлежит дисциплине. Три кабинета работают в одном приложении и одной базе.

| Роль | Обязательные функции |
|---|---|
| Студент | Вход по номеру студенческого. Профиль, однократный ввод ФИО, смена пароля и темы. Расписание с фильтрами. Запись, отмена до начала и история собственных занятий. |
| Преподаватель | Вход по рабочему логину. Просмотр назначенных дисциплин. Создание, просмотр, редактирование и отмена своих занятий. Список студентов с ФИО, группой и курсом; фильтры и выгрузка Excel. |
| Администратор | Создание студентов, преподавателей и администраторов. Справочники групп и дисциплин; назначение преподавателей. Исправление данных, отключение аккаунтов, сброс пароля и блокировки. Все занятия, записи, импорт CSV и история действий. |

### Ввод и исправление ФИО

Студент подтверждает правильность ФИО перед первым сохранением. Последующие изменения с его стороны запрещены. Администратор исправляет ФИО по личному обращению, указывая основание. Прежнее значение, новое значение и исполнитель сохраняются в истории. Первичную достоверность ввода подтверждает студент.

## Вход пароли и блокировки

| Правило | Требуемое поведение |
|---|---|
| AUTH 01 | Роль определяется паролем при общем логине преподавателя и администратора. У разных ролей одного логина текущие и начальные пароли должны различаться. |
| AUTH 02 | Пароль студента после создания или обычного сброса — Student. Пароль преподавателя — фамилия в согласованном транслите: Табельская → Tabelskaya, Бой → Boj. |
| AUTH 03 | Считаются неуспешные попытки при заполненных обоих полях. Пустые и чрезмерно длинные поля отклоняются до проверки. |
| AUTH 04 | Десятая ошибка блокирует логин на 5 минут. Попытки внутри паузы не увеличивают счётчик. |
| AUTH 05 | После паузы сохраняется 10 ошибок. Следующие пять ошибок приводят к блокировке до обращения к администратору. Успешный вход очищает счётчик. |
| AUTH 06 | Блокировка принадлежит введённому нормализованному логину. У преподавателя и администратора с одним логином она общая. |
| AUTH 07 | Администратор восстанавливает начальный пароль выбранной роли, снимает общую блокировку и завершает сеансы этого логина. |
| AUTH 08 | При блокировке единственного администратора предусмотрено восстановление из консоли сервера с вводом нового пароля. |

### Хранение и изменение паролей

Хранятся хеши scrypt текущего и начального паролей. Новый собственный пароль содержит 8–128 символов, подтверждается повторным вводом и не совпадает с начальным или паролем другой роли того же логина. После смены остальные сеансы аккаунта отзываются.

Счётчик не хранится в браузере или памяти одного процесса. PostgreSQL обеспечивает его сохранность при перезапуске и последовательную обработку одновременных попыток. Для неизвестного логина учитывается введённая строка: восстановить задуманный пользователем логин из опечатки невозможно.

В деморежиме смена начального пароля добровольная. Параметр FORCE_INITIAL_PASSWORD_CHANGE позволяет требовать её после создания или сброса аккаунта.

| Правило | Требуемое поведение |
|---|---|

| BOOK 02 | Преподаватель создаёт занятия только по назначенным ему дисциплинам. Одна дисциплина может иметь нескольких преподавателей. |
| BOOK 03 | Пересечение запрещено по всей длительности: 16:00–17:00 и 16:30–17:30 конфликтуют. Соседние интервалы 16:00–17:00 и 17:00–18:00 допустимы. |
| BOOK 04 | Студент не может иметь две активные записи на пересекающиеся интервалы, независимо от преподавателя и дисциплины. |
| BOOK 05 | Проверяются заполненное ФИО, действующий аккаунт, совпадение курса и группы, свободные места, отсутствие активного дубля. |
| BOOK 06 | Запись разрешена при начале не раньше чем через 48 часов. При меньшем остатке занятие видно, кнопка выключена; прямой POST тоже отклоняется. |
| BOOK 07 | Студент может отменить запись до начала занятия. Повторная запись после отмены проходит все обычные проверки. |
| BOOK 08 | После первой записи время, преподаватель, дисциплина, курс и группа занятия неизменяемы. Перенос осуществляется отменой и созданием нового занятия. |
| BOOK 09 | Отмена занятия отменяет все связанные активные записи в одной транзакции. Студент видит отмену в своём кабинете. |

В PostgreSQL время хранится как timestamptz; интерфейс отображает часовой пояс Asia/Yekaterinburg, UTC+5. Интервалы имеют вид [начало, окончание). Администратор может менять аудиторию и описание, сохраняя историю основного расписания.

## Модель данных и управление базой

| Таблица | Содержимое и основные связи |
|---|---|
| users | ID, логин, роль, ФИО и его фиксация, группа, курс, форма обучения, текущий и начальный хеши пароля, активность, тема, версия сеансов. |
| groups | Группа и признак активности. У студента одна текущая группа через users.group_id. |
| subjects | Дисциплина и активность. |
| teacher_subject | Связь многие-ко-многим между преподавателями и дисциплинами. |
| events | Очное занятие; ссылки на преподавателя, дисциплину и группу; интервал времени, аудитория, вместимость и статус. |
| bookings | Запись студента на занятие, согласованный интервал, статус, время регистрации, посещаемость. |
| login_gates | Нормализованный логин, число ошибок, конец паузы, постоянная блокировка. |
| audit_log | Исполнитель, действие, объект, подробности и время изменения. Содержит также события выгрузки журнала. |

Уникальность аккаунта задаётся парой логин/роль, записи — парой студент/занятие. Внешние ключи не допускают «потерянных» ссылок. GiST EXCLUDE запрещает пересечения преподавателя и студента. Составной внешний ключ связывает интервал записи с интервалом занятия.

### Что означает управление БД из кабинета

Администратор меняет прикладные данные через понятные формы. Flask проверяет права и корректность, затем фиксирует транзакцию PostgreSQL. SQL-пароль и соединение с БД не передаются в браузер. Произвольный SQL из интерфейса не вводится.

Отключение и архив сохраняют исторические записи. Логин и роль существующего аккаунта не меняются: ошибочный аккаунт отключают и создают правильный. Пустая группа допускается на стадии подготовки импорта. Журнал Excel отражает актуальные ФИО, группу и курс; отдельная история переводов между группами не ведётся.

## Интерфейс и технические требования

### Состав реализации

Flask 3.1; Jinja и локальные HTML/CSS/JS; SQLAlchemy 2.0; psycopg 3; PostgreSQL 16; Alembic; Waitress; openpyxl. pgAdmin 4 подключается к той же PostgreSQL отдельно. Основной вариант запуска — Docker Compose с Python 3.11; также предусмотрена обычная установка Windows/Linux.

Интерфейс на русском языке, понятные подписи и ошибки, адаптация к мобильному экрану, светлая и тёмная темы.

Студент видит расписание и собственные записи. Преподаватель видит только своих участников. Администратор имеет общий обзор.

Списки разбиты на страницы. У преподавателя есть просмотр по дисциплине и группе. Журнал выгружается в XLSX, до 10 000 строк за запрос.

Импорт студентов — CSV UTF-8 с разделителем «;», полями login, group, course, study_mode. До 500 строк и 1 МБ. При ошибке откатывается весь импорт.

Новые пользователи создаются только администратором. Публичной регистрации нет. Восстановление доступа выполняется по личному обращению.

### Права и целостность

Разграничение прав проверяется на сервере при каждом обращении. Изменения выполняются через POST с CSRF-токеном. Пароли хешируются; сеансы подписаны и могут отзываться. Выгрузка Excel не исполняет введённые пользователями формулы. Автоэкранирование шаблонов защищает отображение введённого текста.

Последнее место резервируется внутри транзакции после блокировки строки занятия. Строка студента блокируется при его записи. Ограничения EXCLUDE в БД дополняют серверную проверку пересечений. Миграции и начальные данные запускаются отдельно от обычного старта приложения.

### Следующие версии

Уведомления по email, устанавливаемая PWA, единый вузовский вход и синхронизация с 1С вынесены в развитие после основной версии. Базовые страницы уже пригодны для компьютера и телефона. Учебные материалы, платежи и онлайн-видеозанятия в текущий объём не входят.

## Приёмочные испытания программы

| Проверка | Ожидаемый результат |
|---|---|
| Три роли | Один логин сотрудника с двумя разными паролями открывает соответствующие кабинеты. Студент не открывает админские маршруты. |
| Профиль | Новый студент сохраняет ФИО один раз. Повторная отправка отклоняется. Администратор исправляет ФИО с основанием. |
| Блокировки | Пустые поля не увеличивают счётчик; 10 ошибок дают паузу 5 минут; после паузы ещё 5 — постоянную блокировку. Сброс восстанавливает вход. |
| Запись | Допустимая запись видна студенту и преподавателю. Дубликат, чужой курс/группа, закрытая запись и переполнение отклоняются. |
| Интервалы | Полное и частичное пересечение запрещены; соседние интервалы разрешены. Проверка действует для студента и преподавателя. |
| Отмена | Отмена студентом освобождает место; отмена занятия меняет статусы всех его записей. |
| Администрирование | Создание всех ролей, назначения дисциплин, исправления и отключения работают и отражаются в истории. |
| Журнал | Фильтры действуют в списке и выгрузке. Чужие студенты не попадают в Excel преподавателя. |
| Одновременные запросы | Из двух запросов на последнее место успешно завершается один. Проверка выполняется на обычном PostgreSQL. |
| Перенос и восстановление | Стенд открывается со второго компьютера. Резервная копия восстанавливается в отдельную БД без потери контрольных записей. |

В протоколе фиксируются версия приложения, среда, дата, шаги, ожидаемый и фактический результат, снимок экрана при необходимости. Реальные измерения производительности и апробация описываются после проведения, а не заранее.

Критический дефект — обход прав, потеря данных, неверная блокировка, двойная запись или превышение мест. К передаче основной версии открытых критических дефектов быть не должно.
